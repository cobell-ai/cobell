# Handle service notices and reauthentication: screen reference

Read service-supplied banners/dialogs and follow the specific action offered.

## Open this screen

**Desktop:** A notice can appear over the main window or replace it for a required update.

**Mobile:** A notice can appear over the app or replace it for a required update.

## Controls

| Control or area | Location and behavior |
|---|---|
| Banner title/message | Explains the service notice. |
| Details / open action | Opens the supplied detail or permitted destination. |
| Close / Dismiss announcement | Dismisses a notice only when allowed. |
| Acknowledge button | Uses the notice’s supplied label or the standard OK action. |
| Sign-in-again action | Starts the requested reauthentication. |
| Required update action | Opens the supplied update route; ordinary interaction is blocked. |
| Unavailable feature page | Reports that the build or service does not offer the requested action. |

## Conditions and results

Notice wording/action labels can be supplied dynamically and should be repeated as shown. Locked notices do not offer a normal dismissal path. A feature-unavailable page is not evidence of a hidden menu the user can enable. Forced logout and optional sign-in-again prompts have different consequences.
