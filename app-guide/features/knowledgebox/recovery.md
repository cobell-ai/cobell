# Review unfinished mobile file changes

Review an interrupted operation in this phone's KnowledgeBox before making another file change.

## Start here

**Desktop:** For desktop workspace problems, open Workspace settings and check the binding; the mobile recovery inspector is not a desktop dialog.

**Mobile:** Third bottom tab Shortcuts → DingDong → select your Pure → Knowledge → Knowledge file recovery, or Review pending changes when shown.

## Desktop steps

1. If a desktop KnowledgeBox folder is unavailable, open Workspace settings.
2. Check the selected folder and reconnect or change to a valid workspace.
3. Do not assume this restores files removed from disk.

## Mobile steps

1. Open Knowledge file recovery or Review pending changes under the affected DingDong using its normal owner account. This checks the current phone's knowledge folder.
2. Wait for the check or use Check again/pull-to-refresh. Read each reason and affected path. After a failed check, any retained details can be stale.
3. Open Inspect files and copies where available. Select Current file and Retained copy rows to inspect text or directories. Use Parent folder, Affected files or Back to return through the inspection.
4. Review Descriptions saved before the change on the overview if present. This is reference information; opening it does not restore those values. A partial preview does not discard the saved content.
5. If you need retained content as a normal file, select its retained file/folder, or use its retained root from the overview, then Copy to a new folder and confirm. The app creates a folder based on Recovered files, reports progress and shows its resulting path. There is no folder-name input in this confirmation.
6. Return to the record overview. Choose Use current files only if you accept the present files, and confirm. This action is shown only for eligible, unaccepted records.
7. Return to the recovery list and Check again. Review other pending records; Done appears after a successful check with no blocking issues. Retained recovery records → Open retained record allows later inspection of accepted copies.

## Completion, limits and recovery

Inspection does not write file contents. Present files do not prove the interrupted operation completed. Missing, unavailable or non-text entries may have no text preview. Unverified records are left in place and may not offer inspection or acceptance.

Copy to a new folder keeps the current files and available source copy; it does not resolve other unfinished changes. Use current files keeps present files, their current descriptions and available recovery records/copies. It does not restore older descriptions or resolve other records.

Read the notice and review affected files and available copies. Use Check again when offered. If copying fails, check storage and connection. Reload an uncertain result before repeating the action.

This inspector is local-folder recovery, not a cross-device backup service. An unavailable folder requires the [workspace controls](https://raw.githubusercontent.com/cobell-ai/cobell/main/app-guide/features/knowledgebox/workspace.md); recreating a missing folder does not restore deleted files.

Also find this under: file recovery, uncertain changes, retained copy, pending import.
