# Rename, delete or describe knowledge entries

Change a file/folder identity or its saved description and summary.

## Start here

**Desktop:** KnowledgeBox tree entry → Menu; metadata fields appear in the selected resource’s header/content panel.

**Mobile:** Knowledge file info/details → Rename, metadata edit or delete action.

## Desktop steps

1. Select the entry and open its Menu → Rename, or press F2 while the tree has focus. Enter/checkmark confirms the inline name; Esc/cross cancels.
2. For metadata, expand Metadata in its opened content tab.
3. Edit Description (up to 500 characters) and Summary (up to 4,000), then Save. This saves metadata rather than file contents.
4. For deletion, use Menu → Delete and review the named file/folder before confirming. Cancel keeps it. A folder includes its contents and metadata.
5. Eligible local entries offer file-explorer/default-app opening in the content header; remote entries do not provide these local actions.

## Mobile steps

1. Open the entry's info sheet and check the selectable relative path, modified date/time, size and available metadata.
2. Choose Rename or Edit description and summary. Save the separate form; keyboard Done also submits a name. Metadata limits are 500/4,000 characters.
3. Back checks changed drafts before leaving; keep editing or discard. If required local metadata is still loading or failed, return after it is available before editing metadata.
4. To delete, check the source/path and file-versus-folder warning, then confirm. Cancel keeps it; pending deletion blocks duplicate actions/leaving.
5. If an operation needs recovery, open Knowledge file recovery and inspect the affected paths before repeating the mutation.

## Completion, limits and recovery

Names are portable single-entry filenames with a maximum of 255 UTF-8 bytes including extension. Invalid/reserved names and existing destinations are rejected. A DingDong can also maintain description and summary; these are separate from file contents.

Deletion affects the owning device, including file metadata and folder contents. The mobile confirmation warns that it cannot be undone. If the form reports a changed workspace or uncertain mutation, return to the list, refresh and review pending recovery before repeating Save/Delete. A completed mutation can still be followed by a failed list refresh.
