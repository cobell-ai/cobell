# Answer questions from a DingDong

Complete the question set so the waiting DingDong can continue.

## Start here

**Desktop:** Click DingDong needs your answer, or use the question controls in the message.

**Mobile:** Tap DingDong needs your answer or the question-answer control.

## Desktop steps

1. Open DingDong needs your answer.
2. Select a suggestion to advance to the next question or review. For a custom answer, type and press Use typed answer in the dialog, or the checkmark or Enter in an inline question bubble. Typing alone does not select desktop's custom draft. The bubble's X hides the input and keeps its draft and the selected answer.
3. Open Review answers and correct any entries. In a multi-question desktop bubble, the send-shaped icon opens review; it does not submit the answers.
4. Click Confirm & send.
5. If answers are incomplete, review the warning before Send anyway.

## Mobile steps

1. Open the waiting question panel.
2. On the waiting-question page, select a suggestion and use Next. Enter directly... switches to custom input and clears a selected suggestion; typing updates the draft. In an inline question bubble, selecting a suggestion advances automatically instead.
3. Use Review answers, then Confirm & send.
4. Explicitly confirm incomplete answers only when intended.

## Attach images or files to a question

1. Under the intended question, choose Add images or Add files. Requested kinds are highlighted; other attachments are still allowed.
2. Select items and wait for upload. Adding them does not submit the answer or resume the DingDong.
3. Check the previews and names. On desktop, click an image preview to open its viewer; click the image or backdrop, Close, or Escape to leave. Mobile question previews and the displayed file names/sizes are read-only. Remove attachment drops an item from the answer draft and keeps the local file.
4. For a failed upload, reselect the failed items, or use Continue without failed items to clear the failure and keep successful uploads. That button does not retry anything. Pending uploads and unresolved upload failures block answer submission.
5. Review the set and Confirm & send. An attachment-only answer is accepted; inspect the file list even if its text preview is blank or says No answer.

The entire question set shares **20 images and 10 files**. Each image is limited to **20 MiB**, each file to **100 MiB**, and each text answer to **1,000 characters**. Too many selected items fail instead of silently dropping extras. Shorten an answer if a length error appears.

## Choose where a composer upload goes

If a normal chat upload opens Where should these attachments go?, choose the intended DingDong and question. Add items in the opened question editor, then review and submit. Send to chat without answering continues an ordinary chat upload; it will not answer the waiting question. Closing this chooser cancels that upload action.

On mobile, scroll the destination sheet to find the question by DingDong name, number and text. Only current unanswered questions requesting that attachment kind appear. This opens an editor before file selection: use Add images or Add files there. It follows the inline bubble's controls, including automatic advance on suggestions and the inline Send anyway warning. After submission, the page stays open with answered questions; use Back to leave.

## Completion, limits and recovery

No suggestion is selected by default. A question with neither text nor attachments is sent as unanswered only after explicit Send anyway confirmation. Desktop and the mobile waiting-question page use a dialog; cancelling it returns without sending. The mobile bubble and upload-destination page show an inline warning and change their submit button to Send anyway. Editing or navigating questions clears this warning, so an incomplete submission asks again.

A failed submission keeps the current editor's answers for retry. Check attachment failures, text length and the current request first. A command lock can briefly disable controls; the mobile bubble shows a sending label during submission. Changed account, room access or run/question state can retire the view or reset drafts. Reopen the current request if necessary. After success, the desktop dialog and mobile waiting-question page close. The inline bubble and mobile upload-destination page show answered questions, which can still be browsed without editing or resending.

Cancel or Back does not submit or stop the run. Text drafts can be lost when closing, and separate question views do not synchronize their text drafts. This editor and its waiting-question control have no Stop action; see [response controls](https://raw.githubusercontent.com/cobell-ai/cobell/main/app-guide/features/dingdongs/response-controls.md) for other states. If the waiting control opens [Shell approval](https://raw.githubusercontent.com/cobell-ai/cobell/main/app-guide/features/security-diagnostics/shell-approval.md), use that request's approval controls instead.

Clicking the desktop dialog's backdrop also closes it. Closing does not cancel a submission already in progress. The mobile waiting-question page blocks Back during submission.
