# Handle service notices and reauthentication

Read service-supplied banners/dialogs and follow the specific action offered.

## Start here

**Desktop:** A notice can appear over the main window or replace it for a required update.

**Mobile:** A notice can appear over the app or replace it for a required update.

## Desktop steps

1. Read the notice’s title and message.
2. Use its Details/open action when present.
3. Dismiss or acknowledge if allowed.
4. For reauthentication, follow the displayed sign-in instruction and wait for logout/cleanup.
5. For a required update, use its update action.

## Mobile steps

1. Read the banner/dialog, including the supplied reason.
2. Open details, acknowledge or dismiss as offered.
3. If reauthentication is requested, finish the sign-out/cleanup and sign in again.
4. Use the required-update action if the app is blocked by version policy.

## Completion, limits and recovery

Notice wording/action labels can be supplied dynamically and should be repeated as shown. Locked notices do not offer a normal dismissal path. A feature-unavailable page is not evidence of a hidden menu the user can enable. Forced logout and optional sign-in-again prompts have different consequences.

Also find this under: banner, service dialog, forced logout, sign in again, unavailable feature.
