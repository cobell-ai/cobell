# Recover an unavailable chat

Check the affected room before repeating a membership or closure action.

## Desktop steps

1. Open the affected shared room, its thread or Chat Room Settings. You can also use the room row's refresh icon outside Edit.
2. Read the status. It can mean the room is unavailable, this device's saved record needs updating, or local removal needs to finish.
3. Choose Check again. Checking… disables the button while the check runs. For a long notice, scroll its text to read the full status.
4. Inspect the result. Recovery is not complete means another attempt may be needed. A compact list icon has no detailed failure text; open the room/settings to inspect it.

A normal signed-in account is required. Follow the current recovery notice. Completing local removal can delete the room and its downloaded data from this device. This room is no longer on this device has no Retry action.

## Mobile steps

1. Open the affected room or thread. Its Checking chat room notice keeps saved messages available in read-only mode while verification runs. Settings and the room row also expose recovery status.
2. If Could not verify chat room appears, choose Retry. The list has an equivalent Retry icon. Retry stays disabled while checking; scroll a long notice to read it fully.
3. Check whether access returned, read-only history remains, or the room was removed locally. Settings can return to Chat after a confirmed removal. Reopening is not guaranteed.

Use the current normal signed-in account. Preview and agent login cannot dispatch the mobile recovery action. Account, room/access or screen changes can retire an old control; reopen the current room rather than using an old view.

For an unfinished mobile Leave chat, open Chat → Pending chat changes, the header icon with a room count. An otherwise empty list can show the same action as a button. Scroll to the room. Sending, checking and cleanup-in-progress rows show progress and cannot be selected. When a row says leaving is unconfirmed or local cleanup needs retrying, tap it to open that room's settings and inspect the existing operation. Selecting the row only opens settings; use that operation's current Check status or Retry there. Close or dismiss the sheet to return without choosing. If its entries finish or the account/page changes, reopen current controls as needed.

## Results and recovery

These actions check room availability or finish pending recovery. They do not resend messages, invite anyone or submit a new Leave/Close request. Use an uncertain action's own Check status control before submitting it again.

A failed read is not proof of deletion. A completed check can still establish closure or ended membership; the notice disappearing is not proof that the room is active. Leaving the screen does not undo a dispatched check or completed local work. The desktop shared-room controls do not apply to single personal DingDong chats.

Also find this under: unavailable room, read-only chat, Check again, Retry room verification, finish local cleanup, saved record pending.
