# Send and open files or images

Attach an ordinary file or image to a message and inspect received content.

## Start here

**Desktop:** Chat panel → open the room → composer → Send image / Send file, or More when the actions collapse.

**Mobile:** Second bottom tab Chat → open the room → composer → image/file action, or More in the compact action strip.

## Desktop steps

1. Open the room and choose Send image or Send file.
2. Select the local content. If Select file or Select image opens, check the subset and Confirm. An ordinary desktop upload accepts up to 10 files or 20 images; the selection screen initially checks the first items up to that limit. Deselect an item before replacing it when the limit is reached. Wait for upload/send completion.
3. For a received file, use Save and choose a destination. Wait for File saved. The name and type icon are read-only.
4. Click a received image preview to open its viewer. Leave by clicking the image, backdrop or Close, or by pressing Escape.
5. Review a displayed external-image address before allowing its fetch.

## Mobile steps

1. Open the composer’s image/file action or More.
2. Choose the attachment and grant picker access if required.
3. Wait for completion; use retry on a failed upload.
4. For a received file, tap Download file. Wait for the download, then choose a destination in the system save/export picker. File saved confirms export; cancelling the picker leaves without saving.
5. Open an image preview to inspect it. Pinch to zoom, drag to move, then Close. A failed image-fetch preview can be tapped to reload while access is current.

## Completion, limits and recovery

Ordinary attachments differ from KnowledgeBox imports and P2P offers. A failed upload is not a sent attachment.

For an external image embedded in Markdown, use desktop View image or mobile Load image, review its HTTPS address, then choose OK on desktop or Open on mobile. Cancel or dismiss leaves the image unloaded. Read-only history can restrict loading to images already cached on the device. On mobile, tap a loaded preview to enlarge it or use a retry control when offered.

Desktop asks where to save a received file before downloading it; mobile downloads before showing the destination picker. The save button shows a spinner during the operation and becomes available again afterward. A failure shows a save-error message. If the mobile account, message or navigation changes, return to the current message before starting another save.

In the desktop selection screen, selecting a thumbnail or file row changes the subset. Confirm is disabled with no selection. Cancel, Close or clicking outside cancels that selection without uploading it. Confirm preserves picker order rather than the order in which you checked items. Question-answer attachments use their own picker flow; see [answering questions](https://raw.githubusercontent.com/cobell-ai/cobell/main/app-guide/features/dingdongs/answer-questions.md).
